# Контракт здоровья и допуска маршрутов

Статус: принят для трека T1, 2026-10-28. Контракт реализует границу проверки
здоровья из [архитектуры](../en/01-architecture.md); он не разрешает изменение
маршрутов и не подтверждает готовность демона.

## Наблюдения

Каждое наблюдение содержит одно из трёх состояний — неизвестно, неработоспособно,
работоспособно — и время начала запроса. Нулевое состояние означает отсутствие
свидетельства. Рабочие probes используют монотонное время Go; наблюдения не
сохраняются и не восстанавливаются после перезапуска.
Наблюдение считается свежим, только если время ненулевое, не находится в будущем
и возраст строго меньше положительного предельного возраста. На самой границе
срока наблюдение уже ничего не разрешает.

Пусть P, R и B означают свежие положительные наблюдения primary, replica и
пулера. Тогда W = P AND B AND NOT R; Q = R AND B AND NOT P. Противоречивые
положительные наблюдения ролей запрещают оба анонса. Неизвестное, отрицательное
или устаревшее состояние пулера запрещает оба анонса. Свежая положительная
проверка одной роли может разрешать соответствующий анонс при неизвестной
второй роли. Это политика ограниченных по сроку наблюдений, а не доказательство
исключительного права СУБД принимать запись.

## Проверка Patroni

Поддерживается REST-контракт Patroni 4.x; целевая версия — 4.1.5.
Ответы старого Patroni 3.x с `role=master` считаются неработоспособными.
Проверяются семантика ответа, а не аттестация установленной версии;
развёртывание отдельно подтверждает закреплённую версию Patroni.

- Доступны только `/primary` и `/replica?lag=<беззнаковое-число-байт>`.
  `/leader` не подменяет проверку primary.
- Обязателен HTTP 200. Тело — JSON-объект в UTF-8, `state=running` и ожидаемая
  роль. Для replica `tags.noloadbalance=true` запрещает допуск.
- Весь запрос, включая чтение тела, ограничен положительным конечным timeout.
  Заголовки и тело независимо ограничены 64 KiB.
- Отклоняются некорректный JSON, дополнительный JSON после документа, повторные
  имена полей корневого объекта и tags, неверные типы используемых полей,
  null или иной тип вместо объекта tags. Неизвестные поля допускаются для
  совместимости с новыми ответами Patroni.
- Переходы по redirect запрещены. Отклоняются userinfo, query, fragment, путь
  и opaque URL. HTTP разрешён только для литерального loopback-адреса;
  остальные endpoints требуют HTTPS с проверкой CA и имени, TLS не ниже 1.3.
- Proxy из окружения не используется. Ошибки не содержат тело ответа.
  Отрицательный HTTP-ответ даёт неработоспособное состояние; ошибка транспорта
  или разбора — неизвестное состояние с ошибкой. Оба случая запрещают допуск.

Проверка lag делегируется endpoint Patroni, использующему WAL-позицию лидера
из DCS; это не независимое измерение replay lag.
Вход пулера предназначен для отдельной проверенной SQL-пробы через локальный
PgBouncer. Открытый TCP-порт не доказывает работоспособность пулера.

## Приёмка трека

T1 требует тестов с настоящими HTTP/TLS-серверами, проверки отмены и ограничения
тела, некорректных ответов, полной матрицы трёх состояний и границ свежести.
Обязательны race tests, vet, форматирование, lint, проверка уязвимостей и
независимая сверка плана, ADR и спецификации. В T1 отсутствуют клиент GoBGP,
изменение маршрутов, production-нагрузка и изменение инфраструктуры.
