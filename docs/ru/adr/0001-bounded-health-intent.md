# ADR 0001: ограниченные наблюдения до изменения маршрутов

Дата: 2026-10-28. Статус: принят для T1.

## Контекст

Принятая архитектура разделяет полномочия Patroni, здоровье пулера и управление
BGP. Проверка только TCP-порта, устаревший успешный ответ, redirect на другой
сервер или неоднозначный JSON способны ошибочно разрешить анонс.
Между независимыми запросами может произойти изменение роли.
T1 должен быть полезен и проверяем без изменения маршрутов.

## Решение

Реализовать внутренние HTTP/TLS-пробы Patroni и чистую политику допуска по
[контракту здоровья](../02-health-contract.md). Runtime использует только
стандартную библиотеку Go. Сохранять время начала запроса, проверять свежесть
при вычислении допуска, запрещать оба анонса при двух положительных проверках
ролей. Deadlines, пределы тела и заголовков, доверие TLS и ограничения URL
проверяются внутри границы probe.

HTTP ограничен литеральным loopback. HTTPS требует проверки CA и имени, TLS 1.3.
Параметра отключения проверки нет. Неоднозначные используемые поля JSON
отклоняются; посторонние поля не запрещаются.

Владение маршрутами, восстановление состояния, SQL-проверки пулера и supervision
относятся к следующим трекам. Демон и выпуск не предоставляются до появления
исполняемых доказательств этих требований безопасности.

## Последствия

Ложный отрицательный результат способен временно запретить анонс, в том числе
при смене роли. Во время медленного запроса или последующей операции наблюдение
может устареть; отсчёт от начала запроса выбран консервативно.
Endpoint только с TLS 1.2 будет отклонён. Требуется его обновление, а не обход
проверки. Допуск маршрута сам по себе не гарантирует fencing или RPO/RTO.

## Проверка

Контракт сопоставляется с настоящими HTTP/TLS-тестами и детерминированными
тестами трёх состояний и свежести. Каждый трек поставки проходит независимую
сверку реализации, результатов тестов, плана, этого ADR и основной спецификации.
