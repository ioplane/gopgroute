# ADR 0003: SQL через локальный пулер

Дата: 2026-10-28. Статус: принято для SQL-подтрека T3.1.

## Основание и решение

Открытый порт PgBouncer не доказывает работоспособность пула БД, правильный
backend и пригодность primary к записи. Использовать pgx v5.11.0, явные
loopback endpoints, SCRAM-only, ограниченный фиксированный SELECT, точную
identity и соответствие recovery/read-only требуемой роли. Первым сообщением
backend требовать `AuthenticationSASL`, чтобы сессия не становилась готовой
без полного SCRAM-обмена драйвера.

Запретить наследование `PG*`, реальные секреты в DSN и raw driver errors.
Результат хранит request-start timestamp и роль; отмена на этапе close
отменяет положительное наблюдение. Контракт:
[SQL-проверка](../04-sql-pooler-contract.md).

## Последствия и проверка

Новые соединения требуют измерения нагрузки аутентификации при выборе
интервала. Read-only monitor на primary блокирует write intent; удалённые
и Unix-backend не входят в текущий контракт. SELECT не доказывает write
durability. Положительные сценарии проверяются реальными PostgreSQL и
PgBouncer, отказы — нативно и protocol fixtures. Требуются контейнерные gates
и независимая сверка плана, ADR и спецификации. Демон, супервизор и полная
приёмка T3 остаются отдельной работой.
