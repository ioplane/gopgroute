# Контракт SQL-проверки пулера

Область: внутренний SQL-подтрек T3.1. Демон и полный T3 не приняты;
независимый супервизор, graceful restart peers и клиентские результаты
остаются обязательными. [Полная спецификация](../en/04-sql-pooler-contract.md).

Подключение выполняется к явному literal-loopback TCP endpoint локального
PgBouncer. Ожидаемый backend PostgreSQL — другой точный loopback адрес/порт.
Оба адреса без IPv6 zone и без IPv4-mapped формы, чтобы один сокет не
сравнивался как два разных endpoint.
DNS, удалённые адреса, NULL identity Unix-backend, multihost, произвольный DSN
и admin-консоль пулера не допускаются. Проверяется alias прикладной БД.

БД, пользователь, пароль и положительный timeout задаются явно. Проверяются
длина, UTF-8 и отсутствие NUL; непустые переменные `PG*` запрещены. Драйвер
pgx v5.11.0 получает фиксированный seed без реального секрета; реквизиты
назначаются полям конфигурации. DSN, argv, ошибки и логи не содержат секретов.
Plaintext, MD5 и trust не принимаются: требуется SCRAM-SHA-256. Первое
сообщение backend обязано быть запросом `AuthenticationSASL`; любое другое
первое сообщение, включая `ReadyForQuery`, `ParameterStatus`, `BackendKeyData`
и `ErrorResponse`, завершает попытку до обработки драйвером. Поэтому ошибка
сервера до аутентификации (нет БД, исчерпаны соединения) возвращается только
фиксированной категорией connect. Защита опирается на проверку подписи
сервера SCRAM закреплённым pgx; при обновлении драйвера её квалифицируют
заново. Транспорт локальный TCP без TLS; доверие к локальному узлу является условием контракта.

Один фиксированный SELECT проверяет БД, пользователя, адрес/порт backend,
recovery и transaction_read_only. При primary оба флага должны быть false,
при replica — true. Адрес извлекается через `host(inet_server_addr())`, без
маски сети. Требуется ровно одна полная строка. Несовпадение — unhealthy;
ошибка протокола, auth, SQL, декодирования или close — unknown. Успешный TCP
handshake сам по себе health не подтверждает. Отмена после чтения строки также отменяет положительный результат, даже при Close=nil.

Единый deadline охватывает connect/query/read/close; сообщения ограничены
64 КиБ. Каждый вызов открывает новое соединение, без prepared caches и
повторов. Используется unnamed extended execution для transaction pooling.
Результат хранит запрошенную роль и monotonic request-start timestamp;
runtime обязан сохранить роль при объединении с Patroni и перепроверить
свежесть перед AddPath. Успешная проверка primary не переносится на replica.

Наружу возвращаются только фиксированная категория ошибки и ошибка context;
raw driver/server errors не передаются. После timeout или отмены pgx v5.11.0
закрывает соединение в фоне: отправляет cancel request и дочитывает сокет до
15 секунд. Проверка возвращается по deadline; интервал runtime-проб обязан
учитывать эти ограниченные фоновые закрытия. READ-only запрос не подтверждает
write I/O, все пользовательские пулы, durability, fencing или HA. Нужны
CONNECT и чтение выбранных builtins, без superuser и прикладного DML.

`make sql-native` проверяет PostgreSQL 18.6 и PgBouncer 1.26.1, primary и
physical standby, несовпадение identity/роли/read-only, потерю backend,
auth downgrade, protocol limits, cancellation и отсутствие утечки ошибок.
Стенд изолирован `--network=none`, запускается непривилегированно, с read-only
rootfs и временным tmpfs; отключённый fsync допустим только для этого fixture.
Нативный CI gate и независимая сверка плана, ADR 0003 и спецификации
обязательны. Весь T3 остаётся отдельной стадией приёмки runtime.
