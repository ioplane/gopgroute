# Контракт владения маршрутами

T2 — внутренняя библиотека Linux. Запуск демона допускается после T3 с
независимым супервизором выделенного GoBGP. Нормативные состояния, ограничения
и критерии: [полная спецификация](../en/03-route-ownership.md).

Задаются два различных IPv4 /32: write и read, один unicast next hop,
положительные сроки RPC и свежести здоровья. Префиксы резервируются за одним
писателем API: проверка ListPath перед AddPath не является атомарным CAS.
Любой существующий путь целевого префикса блокирует добавление. IPv6,
агрегация и несколько next hop в текущий контракт не входят.

Право удаления даёт только ненулевой 16-байтовый UUID из успешного ответа
AddPath. ListPath GoBGP 4.10.0 не возвращает UUID; удаление без UUID и пути
может удалить всё семейство. Удаление по префиксу или семейству запрещено.

Журнал хранится в заранее созданном каталоге владельца сервиса с режимом
0700. Файлы — обычные, 0600, одна жёсткая ссылка; symlink, чужой UID,
повреждённый JSON, несовпадающая конфигурация и второй владелец блокируются.
Нужны доверенные родительские каталоги, локальная ФС с fsync и flock.
Запись: create-only staging → fsync файла → rename → fsync каталога.

| Состояние | Переход |
|---|---|
| Пусто | Сохранить pending-add перед AddPath |
| pending-add | После успешного AddPath сохранить owned(UUID) |
| owned(UUID) | Сохранить pending-delete перед удалением UUID |
| pending-delete | После успешного DeletePath сохранить пустое состояние |

Свежесть T1 проверяется после предварительного чтения RIB и сохранения
pending-add, непосредственно перед RPC; срок RPC ограничен временем жизни
наблюдений. Просроченный успешный анонс отзывается по UUID. Неоднозначный
ответ или ошибка сохранения блокирует дальнейшие изменения. Автоповтора
AddPath и восстановления по совпадению префикса нет.

При старте pending-состояние запрещает работу. Из owned допускается только
отзыв известного UUID до нового допуска здоровья. Неизвестный UUID после
перезапуска GoBGP блокирует восстановление, чужой замещающий путь сохраняется.
Сброс журнала требует отдельно доказанного чистого экземпляра speaker.
Жизненный цикл manager ограничен одним экземпляром speaker. T3 обязан
прекращать manager при выходе, перезапуске или замене speaker и выполнять
startup reconciliation новым manager. Успешный Reconcile не является
аттестацией RIB: неизменённый owned intent не вызывает новый RPC, а ListPath
не доказывает сохранение UUID даже при наличии того же префикса.

Используется private Unix socket 0600 в каталоге 0700 владельца сервиса,
без прикладных повторов gRPC. Close сохраняет маршруты и журнал для
восстановления; штатный отзыв и обработка аварий относятся к T3. Ошибка RPC
не доказывает отзыв. Файловый I/O может зависнуть дольше RPC deadline:
независимый супервизор обязан остановить выделенный speaker и учесть
сохранение stale routes у peers. Это не заменяет fencing Patroni/DCS/watchdog.

Нативные тесты проверяют чужие пути, занятый префикс, перезапуски адаптера и
speaker, потерянные ответы после реальной мутации, UUID, журнал и свежесть.
В конце трека обязательна независимая сверка с планом, ADR и спецификацией.

## Проверка зависимости

На 2026-10-28 база Go отмечает GO-2026-4736 для всех GoBGP v4 без fixed
version. Закреплённый v4.10.0 содержит указанный в advisory fix
583080a7258e22cc884162e15b078771aa2c2c80; неизменённый upstream-тест
`TestRecvMessageWithError_MalformedNextHop` проходит с race detector для
treat-as-withdraw и session-reset. Это проверка конкретной исходной версии,
не приёмка установленного speaker. Сканер остаётся включённым без подавления.
При обновлении зависимости повторяются проверка базы, ancestry и regression.
Сервер GoBGP импортируется только нативными тестами без BGP peers. Два
HTML advisory x/net устранены закреплением v0.62.0. Источники приведены в
[английской спецификации](../en/03-route-ownership.md#dependency-advisory-qualification).
